# 互动小说增强系统 · TauriTavern / SillyTavern 扩展

> **只有两个模式：💬 对话（我是主角）｜✏️ 编辑（我是作者）。**
> 其余复杂性由 Agent 在内部承担 —— 不需要切换角色卡，不需要记特殊指令，不需要填表格。

一套「一张通用故事卡 + 一条长期聊天 + 世界书」的互动小说工作流扩展，
面向 [TauriTavern](https://github.com/Darkatse/TauriTavern)（手机/桌面原生酒馆），
同时兼容 SillyTavern 1.13+。

---

## 它解决什么问题

| 痛点 | 本扩展的做法 |
| --- | --- |
| 想扮演主角，但 AI 总替你做决定 | 对话模式注入导演规则：AI 只负责其余人物，不替主角宣告重大决定 |
| 多个人物像轮流发言，不像真人 | 导演规则显式禁止轮流回复，允许打断、争执、沉默与同时行动 |
| 想改剧情、加设定，却要背一堆指令 | 编辑模式：用自然语言说就行，系统自己判断是改正文还是改资料 |
| 改完设定，长期摘要里还留着旧事实 | 纠错同步：作者否定某项设定时，正文、世界书与记忆一起改 |
| 人物越写越多，世界书一团乱 | 内置条目规范与质量校验：类型/子类、关键词禁忌、数据库式写法、破绽自检 |
| 角色卡换来换去，剧情断裂 | 全程一张卡一条聊天；人物上下场只影响当前场景，资料与经历不丢 |

## 安装

三种方式，任选其一。**推荐 A（手机最省事）。**

### A. 酒馆助手脚本（推荐，手机最方便）

1. 确保已安装并启用 **酒馆助手（Tavern Helper / JS-Slash-Runner）**。
2. 打开 `tavern-helper/if-enhancer-script.json`，把整个文件内容复制。
3. 酒馆助手 →「脚本库」→「导入脚本」，粘贴该 JSON。
4. 导入后脚本默认是**关闭**状态，手动打开它。
5. 刷新酒馆页面。输入框上方应出现「💬 对话 ｜ ✏️ 编辑」。

> 引导器只做一件事：从 jsdelivr 把扩展本体加载进酒馆页面，因此推送后会自动跟随更新。
> 注意：未指定版本号时 CDN 缓存最长约 **7 天**；需要立刻生效可在
> [jsdelivr purge](https://www.jsdelivr.com/tools/purge) 提交 `cdn.jsdelivr.net` 形式的链接刷新。
> 想要离线可用请改用方式 B（扩展目录）。

### B. 扩展目录（离线可用）

把本仓库整个文件夹放进酒馆扩展目录，然后在「扩展」面板里启用：

| 环境 | 目录 |
| --- | --- |
| SillyTavern | `data/default-user/extensions/tauritavern-if-enhancer/` |
| TauriTavern（安卓） | 应用数据目录下的 `data/default-user/extensions/tauritavern-if-enhancer/` |

### C. 从 URL 安装（桌面酒馆）

「扩展」→「安装扩展」→ 粘贴：

```
https://github.com/KarasjokMing/tauritavern-if-enhancer
```

安装后可开启自动更新。注意：酒馆的 URL 安装会把**仓库根目录**整个克隆到扩展目录，
因此 `manifest.json` 必须位于仓库根（本仓库满足该要求）。

### 依赖

| 能力 | 是否需要酒馆助手 | 说明 |
| --- | --- | --- |
| 对话模式导演规则 | 否 | 只用酒馆消息读写 |
| 编辑模式：生成与修订正文 | **是** | 需要 `generateRaw`／`generate` |
| 编辑模式：结构化输出（任务分类、条目生成） | **是** | 无酒馆助手时退回文本解析，稳定性下降 |
| 世界书读写 | 否 | 优先用酒馆助手世界书 API，否则走 `/api/worldinfo/*` |
| TT Agent 通路 | 否（实验性） | 需要 TauriTavern 宿主 |

## 快速上手（三步）

1. **准备一张通用故事卡 + 一条长期聊天。** 世界书建议留空或只放基础世界观，其余交给扩展维护。
2. **对话模式**：直接以主角身份说话。

   > 张婆，这个月的租子该交了吧？——我走进院子，顺便打量旁边洗衣服的年轻女子。

3. **编辑模式**（点输入框上方的「✏️ 编辑」）：用自然语言下指令。

   > 突然下雨，张婆一反常态地走进雨中。

   输入框会变色并提示「作者指令」，此时你说的话是作者视角，不会被当成主角台词发出。
   指令本身会显示在执行回执里（可选同时记为聊天里的隐藏消息）。

### 这条按什么处理：演绎剧情 / 更改配置 分开

编辑模式的模式条里有一个选择器，选中什么就按什么处理，**分类器不参与**：

```
💬 对话 ｜ ✏️ 编辑
  这条按什么处理：[自动判断 ▾]
    ├ 自动判断（默认，交给分类器）
    ├ ✏️ 演绎剧情（写新正文）
    ├ ⚙️ 更改配置（生成参数/偏好）   ← 不产生正文，写进世界书「作者偏好」
    ├ ✏️ 修改正文（改已有回复）
    ├ 👤 创建人物 / 👤 修改人物
    ├ 📚 写入世界书
    └ 🗂 整理记忆
```

- 想写剧情就选「演绎剧情」，想调整生成方式（推进速度、节奏、篇幅、文风、尺度）就选「更改配置」——
  两者彻底分开，不会再出现"配置指令被当成正文写进故事"。
- 选「自动判断」时也不会乱猜：连模型都无法定性时，系统会明确询问而不是默认当正文处理。

### 作者偏好（更改配置都记在这里）

「更改配置」类指令**不产生正文**，而是：

1. 记入扩展设置，立即注入对话模式的提示层；
2. 写进世界书的「作者偏好」常驻条目（类型：扮演准则），随生成上下文长期生效。

例如「推进速度设为快」「每次回复短一点」「不要替主角做决定」。
设置面板里可以查看与清空。基础条目规范见 [`docs/WORLDBOOK_SPEC.md`](docs/WORLDBOOK_SPEC.md)。

### 编辑模式能做什么

| 你想做的事 | 直接说的话 |
| --- | --- |
| 安排天意 | 「突然下雨，张婆一反常态地走进雨中。」 |
| 演绎梗概 | 「主角来到坡子口催租，发现柳如烟身上有灵气。张婆准备赶她走，主角替她交了租。」 |
| 纠正剧情 | 「刚才那段其他都不错，但坡子口只是普通凡人聚居区，不存在大量修仙高手。」 |
| 修改人物 | 「柳如烟不要那么冷漠，应该更善于伪装，表面上温婉随和。」 |
| 创建人物 | 「创建一个合欢宗长老，女性，年约四十，修为金丹后期，性格比较严肃，其余自行发挥。」 |
| 收录设定 | 「根据目前剧情整理坡子口和张婆的设定，写入世界书。」 |
| 整理记忆 | 「把目前已经发生的主要事件总结一下，顺便检查有没有矛盾。」 |
| **更改配置** | 「推进速度设为快。」「每次回复短一点。」「不要替主角做决定。」 |

**不存在**额外的天意模式、旁白模式或世界书模式 —— 全部属于编辑模式。

## 结果怎么呈现

- **正文类操作**（演绎、修订）→ 结果进入聊天记录，成为故事的一部分。
- **资料类操作**（收录设定、更新档案、整理记忆）→ **不产生正文**，只在输入框上方显示执行回执：

  > ✓ 已更新人物档案：柳如烟
  > ✓ 坡子口·互动小说：新增 2 条，更新 1 条

回执可展开查看详情；修订正文类操作提供「↩ 撤销这次修改」。

## 世界书规范

内置条目规范（条目类型与子类、策略与位置推导、关键词禁忌、质量校验）为**独立实现**，
详见 [`docs/WORLDBOOK_SPEC.md`](docs/WORLDBOOK_SPEC.md) 与 [`NOTICE.md`](NOTICE.md)。

要点：

- **蓝灯/绿灯自动推导**：世界规则常驻；同类条目数量达到阈值后自动转为关键词触发。
- **关键词禁忌**：严禁单个汉字（`樱` → `小樱`）、避免泛用职务（`老师` → `语文老师`）、避免成语。
- **写作规范**：数据库格式而非散文；不写占位符；条目必须独立可读；统一简体。
- **质量校验**：破折号、八股表达、模糊词、元叙事泄漏、繁体字、跨条目引用与重名都会被标出。
- **记忆独立存放**：长期记忆写为 `[记忆] …` 系列的常驻条目，与小说正文分离，随世界书一起进入上下文。

## TauriTavern Agent 配置档案（可选）

`profiles/` 目录提供三个 Profile（JSON，符合 `tauritavern.agentProfile`）：

| 文件 | 用途 |
| --- | --- |
| `if-author.json` | 前台：按作者要求演绎/修订正文并提交为聊天消息 |
| `if-memory.json` | 后台：整理长期记忆到 `persist/summary.md`，不插入聊天 |
| `if-lorekeeper.json` | 后台：从剧情提炼世界书草稿到 `persist/lore-draft.md` |

安装：Agent 面板 →「配置档案」→ 导入对应 JSON → 重新选择模型（Profile 不携带模型连接）。

`skills/interactive-fiction/` 是配套的 Skill，供 Agent 查阅条目与记忆规范。
导入方式：Agent 面板 → SKILLS → 导入该目录。

> **实验性说明**：扩展的正文生成默认走酒馆助手通路（行为可预期）。
> TT Agent 通路需要真机验证后才能作为主路径，当前作为后台整理与后续升级的入口保留。

## 真机验证（TauriTavern / 安卓）

已在 **TauriTavern + 酒馆助手** 的安卓真机（Android 16，adb 无线调试）上完成端到端验证：

| 验证项 | 结果 |
| --- | --- |
| 模式条挂载 | `💬 对话 ✏️ 编辑` 两个按钮 + 提示语挂在输入框上方（视口 400×890） |
| 能力探测 | 酒馆助手 ✓、`generateRaw` ✓、TT Agent ✓、世界书后端 = 酒馆助手 API |
| 对话模式 | 导演规则成功注入（`setExtensionPrompt`） |
| 编辑模式·正文 | 路由 `prose.generate`，生成 1029 字中文正文并追加为聊天消息 |
| 编辑模式·世界书 | 路由 `worldbook.write`，写入条目并给出真实校验反馈 |
| 编辑模式·人物 | 路由 `character.create`，条目名与关键词正确 |
| 落盘字段 | 地理 `position=0`、角色 `position=1`、`selective/constant`、`order` 推导均正确 |
| 无聊天保护 | 未打开聊天时明确报错，不会静默丢消息 |

排障工具与步骤见 [`docs/INSTALL.md`](docs/INSTALL.md) 的「手机端远程自检」一节。

## 已知边界

- 「编辑模式的正文生成」依赖酒馆助手的 `generateRaw`／`generate`；没有它时退回 STscript `/genraw`，能力较弱。
- **供应商结构化输出**：部分 API（实测 DeepSeek）不支持 `json_schema` 对应的 `response_format`。
  扩展会自动降级为「纯文本 + 强 JSON 约束 + 一次转换成 JSON 的修复重试」，并把这个结论记住，
  诊断里显示为 `结构化输出 △`。更换模型后可在设置面板点「重新尝试结构化输出」。
- 修订正文的目标默认是**最后一条 AI 回复**，也可用「上一条」「第 3 条」指定。
- 自动记忆按回复条数触发，不做每轮整理；场景变化触发与固定间隔触发属于后续计划。
- 人物条目在同类条目少于阈值时按规范恒为常驻（关键词不生效），这是条目规范的推导结果而非缺陷；
  校验会在回执里提示。
- 移动端交互（小屏下的回执高度、输入法回车行为）已按 400×890 竖屏布局，但仍建议真机手感再调一轮。
