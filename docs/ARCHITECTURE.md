# 架构说明

## 1. 一句话模型

```
输入框旁的开关 ──┬─ 对话模式 → 注入导演规则 → 酒馆原生生成（用户＝主角）
                └─ 编辑模式 → 分类指令 ──┬─ 正文类：改写/新增聊天气泡
                                        └─ 资料类：写世界书 / 更新记忆 → 界面回执
```

同一条聊天、同一张角色卡、同一本世界书贯穿始终；人物上下场只影响当前场景。

## 2. 分层

| 层 | 文件 | 职责 |
| --- | --- | --- |
| 宿主适配 | `src/env.js` | 探测 TauriTavern / 酒馆助手 / ST 能力，统一事件与设置读写 |
| 设置 | `src/config.js` | 默认值、深合并、类型纠正 |
| 提示词 | `src/prompts.js` | 导演规则、任务分类、正文演绎/修订、条目与记忆生成、纠错比对 |
| 交互 | `src/ui/*` | 模式切换、执行回执、设置面板与诊断 |
| 编排 | `src/main.js` | 生命周期、输入截获、事件订阅 |
| 业务 | `src/core/*` | 分类、注入、消息读写、生成、记忆、任务分派 |
| 世界书 | `src/worldbook/*` | 规范常量、推导、校验、读写后端、条目装配 |

依赖方向单向：`ui → core → worldbook → env`，`worldbook` 不反向依赖 `core`。

## 3. 对话模式

1. `refreshDialogueInjection()` 组装文本 = 导演规则 + 故事当前状态（记忆）+ 临时表现指引。
2. 通过 `ctx().setExtensionPrompt(key, text, position, depth)` 注入提示层，**不改聊天记录**。
3. 切换聊天、修改设置、编辑任务完成后重新计算。
4. 切到编辑模式时立即清除注入，避免作者指令被导演规则影响。

导演规则要点：用户只控制主角；AI 负责其余人物与环境；多人物可打断、争执、同时行动；
不得替主角作重大决定；日常回复以交互为主，不强行写长篇。

## 4. 编辑模式

### 4.1 输入截获

在 `document` 上以**捕获阶段**监听 `#send_but` 点击与 `#send_textarea` 的回车，
命中后 `preventDefault + stopPropagation`，因此消息不会被酒馆当作主角台词发出。
（酒馆把发送处理器绑在元素自身，捕获阶段的监听一定先于它执行。）

### 4.2 任务分类

`src/core/router.js`：

1. 关键词打分（记忆整理 / 世界书 / 创建人物 / 修改人物 / 正文修订 / 正文演绎）。
2. 显式词优先：出现「世界书 / 条目 / 收录 / 建档」且不涉及正文 → 世界书任务。
3. 置信度 < 0.6（例如"修改人物"但判断不出是当前表现还是设定本身）→ 交给模型判定，
   用 `json_schema` 拿到结构化路由结果。
4. 模型失败时回退启发式结果，不中断流程。

### 4.3 任务分派

| 任务 | 处理 |
| --- | --- |
| `prose.generate` | 记忆 + 最近历史 + 作者要求 → 生成正文 → 追加为一条 AI 消息 |
| `prose.revise` | 定位目标消息（默认最后一条 AI 回复）→ 重写 → 覆盖该消息；保留原文以便一键撤销 |
| `character.create` | 生成人物档案 → 组装条目 → 校验 → 写入世界书 |
| `character.update` | `scope=performance` 写入临时表现指引；否则改写人物档案条目 |
| `worldbook.write` | 结构化生成条目集合 → 推导策略/位置/顺序 → 校验 → 写入 |
| `memory.summarize` | 读取历史 → 生成记忆结构 → 写入 `[记忆] …` 条目 |

**纠错同步**：路由结果带 `needs_fact_fix` 时（作者否定了某项已记录事实），
正文修订完成后再执行 `applyCorrection()`：把世界书与记忆里的候选事实交给模型比对，
输出冲突编号与替换文本，逐条替换或追加"依据作者更正"版本，**不做叠加式新增**。

### 4.4 结果呈现

| 类型 | 呈现 |
| --- | --- |
| 正文类 | 进入聊天记录，成为故事内容 |
| 资料类 | 只显示在输入框上方的回执条（`src/ui/resultbar.js`），不写入聊天气泡 |

回执条支持展开详情（改了哪些条目、校验提醒）、`↩ 撤销`（正文覆盖类）、以及运行中的状态行。

## 5. 世界书

### 5.1 读写后端（自动降级）

| 优先级 | 后端 | 判定 | 结构 |
| --- | --- | --- | --- |
| 1 | 酒馆助手世界书 API | 存在 `getWorldbook` 且 `createWorldbookEntries` | `WorldbookEntry`（新结构） |
| 2 | 酒馆服务端端点 | 存在 `getRequestHeaders` | 扁平结构（`key`/`comment`/`position` 数字） |
| 3 | 无 | — | 明确报错，不静默失败 |

写入一律走 **读 → 合并（按条目名 upsert）→ 写 → 回读** 的路径；
`ensureWorldbook` 只在确认不存在时创建（酒馆助手的 `createWorldbook` 对已存在的书是覆盖语义）。

### 5.2 规范与推导

- 条目类型与子类、阈值表、位置分组见 `src/worldbook/spec.js`。
- 蓝灯/绿灯推导：同类型同子类的条目数达到阈值才转绿灯；速览级与重述级不参与计数。
- 位置推导：按类型分组决定注入点；重述类强制 `at_depth`。
- 顺序推导：十位分组递增，重述类逆序追加末尾。
- 校验见 `src/worldbook/lint.js`（关键词禁忌、破折号、八股、模糊词、元叙事、占位符、繁简、跨条目引用、重名）。

### 5.3 记忆的物理形式

长期记忆 = 一本世界书里的固定名称常驻条目：

```
[记忆] 剧情摘要
[记忆] 当前场景
[记忆] 人物状态
[记忆] 未完成线索
[记忆] 已纠正事实
```

好处：无需额外存储；随世界书一起进入生成上下文；与小说正文物理分离；
被推翻的事实在「已纠正事实」里留痕而不是被删除。

## 6. 生成通路

| 优先级 | 通路 | 用途 | 说明 |
| --- | --- | --- | --- |
| 1 | 酒馆助手 `generateRaw` / `generate` | 全部生成；结构化输出用 `json_schema` | 主路径 |
| 2 | TauriTavern Agent API | 后台记忆/条目整理（`presentation: background`） | 实验性 |
| 3 | STscript `/genraw` | 无酒馆助手时的兜底 | 提示词里的 `|` 会被替换为全角，能力较弱 |

`startRunFromLegacyGenerate` 的已确证约束：仅当前 active chat、必须 chat-completion 路径、
`stream` 必须为 `false`、不能混用 Legacy external tools。
因此扩展**不**把正文生成放在 Agent 通路上做主路径，而是保留为后续升级入口。

## 7. 兼容性设计

- 不依赖任何酒馆内部模块路径，只用 `SillyTavern.getContext()`、公开事件与酒馆助手公开 API。
- 事件名通过 `ctx().eventTypes` 常量解析，取不到时按字面量回退。
- 消息读写优先酒馆助手 API，缺失时回退 `ctx().chat` 数组。
- 界面注入点固定在 `#send_form` 之前的独立容器（`#tt-if-dock`），
  并用 `MutationObserver` 在酒馆重绘后自动补挂；编辑模式通过 body class 与边框变色提示。
- TauriTavern 的 ChatSurface（消息投影）不涉及本扩展：我们不渲染楼层 iframe，只做输入区与数据层。

## 8. 测试

`tests/run.mjs` 覆盖推导、校验、字段映射、任务分类与设置合并（28 项，纯函数、零依赖）。
`tools/check.mjs` 逐个导入模块（同时验证语法与依赖完整性），并校验
`manifest.json` 必需字段、Profile 的 `kind`/`id`/`messageBody` 产物与工作区权限一致性、
Skill 的 frontmatter。
